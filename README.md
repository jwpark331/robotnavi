# 보이지 않는 계단

광운대 로봇내비게이션 텀프로젝트 (박정원 · 박준우).

2D LiDAR로 만든 SLAM 지도에는 내려가는 계단이 빈 바닥으로 찍힌다. 현장의 두 방어(운영자가 그리는 keepout, 하향 IR 센서) 사이에 깊이카메라 층을 하나 더 넣는다.

- 깊이카메라 → 셀별 베이즈 log-odds 필터 → **odom 좌표에 기억** → Nav2 keepout 마스크
- 마지막 방어는 하향 IR (최종 제안 **P3i**)

검증은 ROS 2 Humble + Gazebo Classic 11 + Nav2로 했고, 원래 노트북에서 1,086회 돌렸다.

처음 보는 사람은 [프로젝트 개요](보이지%20않는%20계단%20—%20프로젝트%20개요.md) → [발표 자료용 정리 (10-23)](보이지%20않는%20계단%20—%20발표%20자료용%20정리%20(2026-10-23).md) 순서로 읽는다.

## 새 노트북에서 시작하기

Ubuntu 22.04 기준이다. 경로는 어디든 되지만, 문서와 맞추려면 `~/robotnavi`에 받는다.

```bash
git clone https://github.com/<계정>/invisible-stairs.git ~/robotnavi
```

ROS 2 Humble이 아직 없으면 먼저 설치한다.

```bash
bash ~/robotnavi/install_ros2_humble.sh
```

필요한 패키지를 깔고 워크스페이스를 빌드한다. sudo 암호를 물어보고, 끝나면 이 컴퓨터 사양을 `results/MACHINE_<호스트명>.txt`에 적는다.

```bash
bash ~/robotnavi/demo_cliff/setup_new_machine.sh
```

Gazebo 창을 띄워 한 회차만 본다. 사람 4명 뒤로 돌다가 계단으로 떨어지면 정상이다.

```bash
cd ~/robotnavi/demo_cliff && GUI=true OUT=results/smoke_$(hostname) SCENS=S2 CONDS=P0 NOREPORT=1 ./run_all.sh
```

원래 노트북과 같은 시드 18회를 돌려 같은 경향이 나오는지 확인한다. 원래 노트북에서는 약 30분 걸렸다.

```bash
cd ~/robotnavi/demo_cliff && ./run_calibration.sh
```

결과는 `results/calib_<호스트명>/compare.md`에 나온다. 맨 아래 판정이 **"같은 경향"**이면 이 컴퓨터에서 새 실험을 돌려도 된다. **"차이가 있다"**면 아래 'GPU·성능 차이'를 본다.

## 실험 스크립트

모두 `demo_cliff/`에서 실행한다. 이미 `result.json`이 있는 회차는 건너뛰므로, 끊겨도 같은 명령으로 이어서 돌리면 된다. 시간은 원래 노트북 기준(회차당 약 1.3–2분)이다.

| 스크립트 | 무엇 | 회차 | 시간 |
|---|---|---|---|
| `SEEDS="1 2 3 4 5" ./run_all.sh` | 본 실험 S1–S4 × P0–P3 | 120 | 3–4시간 |
| `./run_sweep.sh` | 밀림 거리·매트 결측률 sweep | 87 | 2–3시간 |
| `./run_darkstair.sh` | 검은 계단 (깊이값 결측) | 98 | 2–3시간 |
| `./run_wetfloor.sh` | 젖은 바닥 (누적 슬립) | 151 | 3–5시간 |
| `./run_walkers.sh` | 움직이는 사람 6명 | 140 | 3–4시간 |
| `./run_memory.sh` | 기억 시나리오 S7·S8 (H1), P3h (H2) | 180 | 4–6시간 |
| `./run_fb1.sh` | 팀원 검토 방어 (P3+, 2×2, 기울기 오차) | 190 | 4–6시간 |
| `./run_calibration.sh` | 새 컴퓨터 재현 확인 | 18 | 30분 |

- 일부만 돌리기: `SCENS="S3" CONDS="P1 P3" SEEDS="1 2 3" ./run_all.sh`
- 창으로 보기: 앞에 `GUI=true`를 붙인다.
- 판정 기준(주 지표, 통계 검정, 장치 결함 처리)은 [판정 기준 (10-20)](보이지%20않는%20계단%20—%20판정%20기준%20(2026-10-20).md)에 실험 전에 고정해 두었다. 새 실험도 같은 기준을 쓴다.

## 다른 컴퓨터에서 낸 결과 다루기

**새 컴퓨터 결과는 원래 결과 폴더에 섞지 않는다.** GPU·CPU가 다르면 렌더링과 통신 타이밍이 달라져, 같은 시드라도 회차별 결과가 조금씩 달라진다. 비교는 같은 컴퓨터 결과끼리만 한다.

- 모든 스크립트는 `RES=`로 결과 폴더를 바꿀 수 있다. 분석 스크립트도 자동으로 그 폴더를 본다.

  ```bash
  RES=results_$(hostname) ./run_darkstair.sh
  ```

- 다른 실험 결과와 비교하는 분석(예: 검은 계단의 결측 0 % 기준선은 `runs/`를 쓴다)은 그 컴퓨터의 `runs/`도 필요하다. 먼저 `RES=results_$(hostname) SEEDS="1 2 3 4 5" ./run_all.sh`로 본 실험을 같은 컴퓨터에서 다시 쌓는다.
- 회차 폴더마다 `machine.txt`(호스트·GPU·커널·패키지 버전)가 남는다. 원래 노트북 환경은 [results/MACHINE_원래노트북_parkjeongwon-950QDA.txt](demo_cliff/results/MACHINE_원래노트북_parkjeongwon-950QDA.txt)에 있다. i7-1165G7, Intel Iris Xe로 렌더링, generic 커널 6.8.0이다.

## GPU·성능 차이

- **커널**: `uname -r`이 `*-generic`인지 확인한다. EVL 실시간 커널(`*-cip*`)에서는 무거운 시뮬 중 멈춘 적이 있어 `run_all.sh`가 실행을 막는다.
- **NVIDIA 하이브리드 노트북**: 기본은 내장 GPU로 렌더링한다. NVIDIA로 돌리려면 `nvidia-smi`가 되는지 확인한 뒤 명령 앞에 `__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia`를 붙인다. 어느 쪽으로 돌렸는지는 `machine.txt`의 OpenGL 줄에 남는다.
- **장치 결함이 잦을 때**: 컨트롤러 TF 경고가 많은 회차는 `tools/find_faults.py`가 결함으로 골라낸다. 실험 스크립트는 같은 시드로 최대 3번 다시 돌린다. 그래도 많으면 다음을 차례로 해 본다.
  - 다른 프로그램을 닫는다.
  - 전원을 연결하고 성능 모드로 바꾼다.
  - `GUI=false`(기본)로 돌린다.
- **멈춘 시뮬 정리**: `tools/kill_sim.sh`

## 결과 올리기

새 컴퓨터에서 실험을 마치면 결과 폴더와 분석을 올린다. 결과는 대부분 텍스트이고, 영상은 회차당 수십 KB다.

```bash
cd ~/robotnavi && git add demo_cliff/results_$(hostname) && git commit -m "결과: <실험 이름> ($(hostname))" && git push
```
